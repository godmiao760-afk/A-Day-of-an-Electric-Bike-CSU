# 动漫风界面示意图 · 通用任务书（所有 sub agent 共用）

## 游戏
《小电驴的一天》：以电动车视角体验中南大学（CSU，长沙）学生骑电动车的一天。
俯视角 2D 小游戏，画面 960×540，Phaser 3，键盘操作。流程：早上宿舍楼下找车 → 校门口选路线（校内有大坡 / 校外有交警）→ 骑车去教学楼 → 车棚停车 → 上课 → 中午/傍晚选吃饭（食堂 / 后湖）→ 晚上找桩充电（23:00 门禁）→ 结算。

## 中南大学场景元素（请尽量用上，让人一眼觉得是中南）
- **岳麓山**作远景 / 天际线；长沙的**樟树**（行道树，浓绿团簇）、秋天的**桂花**、湿热的夏天
- **宿舍楼**（如升华公寓那种）：6~7 层，白瓷砖/红砖外墙，阳台晾衣服、空调外机；楼下**车棚挤满电动车**，车挨车停，雨棚
- **校内大坡**：校本部地势起伏，骑车上坡很耗电；路两侧樟树
- **校外路线**：麓山南路/桃子湖路一带，小汽车、公交、**交警检查点**（锥桶、路障）
- **后湖**：后湖国际艺术区，湖水 + 烧烤摊 + 文艺小店
- **新校区教学楼 / 图书馆**：灰白色现代建筑
- **晚上充电**：宿舍楼下一排充电桩（扫码充电、有的被占、有的坏了屏幕不亮），路灯昏黄，宿舍窗户透出灯光，远处门禁时间 23:00
- 不要画真实校徽；校门匾额可以写"中南大学"字样

## 游戏 UI 约定（必须出现在界面上）
- 左上角：**电量条**（例如 62%），骑行场景加 **3 格血量**
- 右上角：**时钟**（例如 07:38）
- 角色头顶：**独白气泡**
- 底部：**操作提示**，如「F 查看 · E 背包」「W 前进 · S 刹车 · A/D 换道」
- 选项弹窗：两个选项横排，高亮当前项，如「守着它」/「回宿舍」
- 主角的车是**黄色**（座套/车身），别人的车偏白/浅色
- **所有车辆俯视、车头朝上**；建筑可以带一点 3/4 俯视的立面感

## 三张必画界面（每张 960×540）
1. **01-findcar 找车 · 早上 07:38**：宿舍楼下车棚，几十辆电动车排成几排，主角（步行小人）在车阵走道里，自己的车被左右夹住、刚被认出变黄；气泡「我的车……停哪来着？」或「终于找到你了！」；右上角时钟旁有**信号格**（越近越满）；底部「F 查看 · E 背包」。
2. **02-ride 骑行 · 早上 07:52**：纵向道路（3 条车道），主角骑车在中间；前方有校车/逆行车，后方外卖车冲上来（屏幕底部闪「！」提示），有行人横穿；路两旁樟树，路面有「上坡」标记或坡道色块；左上电量 + 3 格血量；气泡「又是这个大坡……电量在哭。」；底部「W 前进 · S 刹车 · A/D 换道」。
3. **03-charge 夜间充电 · 22:47**：宿舍楼下一排充电桩，有被占、坏了、空闲、已插上发绿光的；主角推车；中间弹窗「终于插上了。守着它，还是先回宿舍？」两个选项；右上时钟 22:47、「门禁 23:00」。

## 另外两项
4. **04-sprites 实际尺寸精灵预览**（比如 720×300 左右）：按游戏里的**真实像素尺寸**画出这个风格的 rider(32×56)、bike(24×48 黄)、bike_other(24×48 近白)、npc_delivery(32×56)、pile(32×40)、road 与 grass 地砖(64×64)，每个画 1× 和 4× 放大各一份，标注名称。目的是让美术判断：这个风格缩到 32 像素还能不能看清。
5. **00-board 总览板**（1920×1080）：标题（风格名 + 一句话定位）、三张界面缩略图、调色板色块（6~10 色带色值）、精灵预览、3~4 条「优点 / 风险 / 美术工作量评估（在 hackathon 几小时内一个美术能否画完 18 张素材）」。

## 技术做法
- 用 SVG 手写（或 Python 生成 SVG），再用 cairosvg 转 PNG：`python3 -c "import cairosvg; cairosvg.svg2png(url='in.svg', write_to='out.png')"`（已装好）。也可以用 Pillow。
- 中文字体：`Noto Sans CJK SC` / `Noto Serif CJK SC`（系统已有）。SVG 里写 `font-family="Noto Sans CJK SC"`。
- 工作区 Linux 路径：`/sessions/stoic-happy-lamport/mnt/Demo1/`；对应 Windows 路径 `D:\Hackathon\Demo1\`。
- **每画完一张，必须用 Read 工具打开 PNG（Windows 路径）亲眼检查**：文字有没有乱码/溢出、元素是否重叠错位、风格是否到位；不满意就改，至少迭代一轮。
- 画面要有细节密度和风格辨识度，不要只是几个色块；但也别追求照片级。
- **只在自己的输出目录里写文件**，不要改仓库里其它任何文件，不要 git 操作。

## 最终回复（给主 agent，简短）
- 输出目录和文件列表
- 风格一句话 + 主色值
- 3 条优点、3 条风险、工作量评估（低/中/高 + 理由）
- 如果选这个风格，美术下一步最该先画哪 3 张素材
