# 《小电驴的一天》美术与动效工作文档

> 依据：`CLAUDE.md` 和现有代码。两者有冲突时以 `CLAUDE.md` 为准。
> 美术素材由 **C** 负责；动效写在各场景代码里，由场景负责人来写（Ride、Class、Result 归 **A**，FindCar、Park、Charge 归 **B**）。

---

## 0. 总体思路

- 游戏里目前全是色块。C 每做好一张图就能马上在游戏里看到；**缺了哪张都不会报错**，那一张会自动继续用色块。所以可以边做边放，不用等全部画完。
- 一张 png 就是一个固定的画面。**绝大部分动效不靠多画帧，用代码让静态图动起来**：在一段时间里平滑地改位置、角度、透明度、大小（Phaser 叫 tween），再加上震屏、变色、粒子。
- 这样做的好处：
  - 俯视角的小精灵只有 32 像素左右，一帧帧画的动画在屏幕上本来就不太看得出来
  - C 的工作量不会翻倍
  - 色块占位也能用同样的动效，程序不用等 C 画完
  - 不用改 `assets.js` 和 `Boot.js` 的约定
- **现状**：6 个场景都已写好第一版，一部分基础动效已经有了（见第 8 节），剩下的是补充。

## 第一部分：美术素材（C）

### 1. 每张图的流程（5 步）

1. 按清单里的尺寸画，**背景透明**，导出成 png
2. 文件名和 key 完全一样，比如 `rider.png`
3. 放进 `assets/img/`（文件夹已经建好）
4. 在 `src/assets.js` 里把这一张的 `file: false` 改成 `true`
5. 用 Live Server 刷新浏览器，看效果

音效也一样：放 `assets/sfx/<key>.mp3`，在 `assets.js` 的 `sounds` 里改成 `true`。

### 2. 风格约定

- **像素风**：`main.js` 里开了 `pixelArt: true`，像素画放大后边缘还是清楚的，不会糊。
- **正上方俯视**：所有车辆**车头朝上**。逆行车也照样车头朝上画，程序会把它上下翻转（`setFlipY`）。
- **按原尺寸画**：比如 `bike` 就在 24×48 的画布上画，不要画大了再缩小。尺寸不对也能显示，但碰撞框会跟着变，会影响手感。
- **统一调色板**：去 Lospec 网站挑一个 16～32 色的调色板，所有图都只用这些颜色，整体才统一。

### 3. 代码会怎么处理你的图（画之前必看）

下面这些都是现有代码里已经在做的事，画图时要配合：

- **`bike_other` 要用接近白色的浅色画**。找车和停车场景会给每辆别人的车随机叠一层淡淡的颜色（`setTint`），让车阵有点区别。叠色是"乘"在原图上的，原图越深越看不出来。充电场景里它就原样摆在被占的桩旁边。
- **`pile` 也要用浅色画**。被占的桩会变灰、坏的桩变深灰、插上电变绿，全靠叠色。
- **主角图会被旋转**。停车场景里 `rider` / `pusher` 会跟着移动方向转（往右走就转 90°），骑行时换道会歪 8°，摔倒转 90°。所以**主体要画在画布正中间**，否则转起来像绕着一个角甩。
- **地面图要能无缝拼接**。`road`、`grass`、`slope`、`building` 都是平铺的，骑行场景里 `road` 和 `grass` 还会跟着镜头一直滚动，有接缝会一直闪。
- **充电场景盖了一层深蓝色夜晚滤镜**，所有图会变暗。`pile`、`pusher` 的对比度要够，否则晚上看不清。

### 4. 图片清单和先后顺序

先做玩家看得最多的，Ride 场景最优先。

| 批次 | key | 尺寸 | 用在哪 | 注意 | 完成 |
|---|---|---|---|---|---|
| 1 | `rider` | 32×56 | 骑行主角；停车场景（骑车进场） | 最重要；会被旋转，画在正中 | ☐ |
| 1 | `road` | 64×64 | 所有场景的地面 | 无缝拼接，骑行时会滚动 | ☐ |
| 1 | `grass` | 64×64 | 骑行两侧、找车场景两边 | 无缝拼接，骑行时会滚动 | ☐ |
| 1 | `npc_delivery` | 32×56 | 骑行：从后面冲上来 | 一眼能认出来，比如黄色或蓝色外卖箱 | ☐ |
| 1 | `npc_wrong` | 32×56 | 骑行：迎面逆行 | 车头朝上画，程序会翻转；和外卖车要明显不同 | ☐ |
| 1 | `npc_walker` | 28×28 | 骑行：横穿马路 | 从正上方看，就是头和肩膀 | ☐ |
| 1 | `npc_bus` | 64×140 | 骑行：挡在前面 | 最大的一张 | ☐ |
| 2 | `bike_other` | 24×48 | 找车车阵、车棚、被占的充电桩 | **接近白色**，程序会叠色；一次出现几十辆 | ☐ |
| 2 | `bike` | 24×48 | 认出自己的车后换成这张；停好车后也显示这张 | 见下方说明 | ☐ |
| 2 | `slope` | 64×64 | 骑行中段的大坡 | 无缝拼接，和平路要分得清；程序会半透明叠在路上 | ☐ |
| 2 | `building` | 64×64 | 场景顶部的宿舍楼、教学楼 | 无缝拼接；上面会压文字，别太花 | ☐ |
| 3 | `player` | 32×32 | 找车时步行 | | ☐ |
| 3 | `pusher` | 40×56 | 没电推车进车棚；晚上推车找桩 | 停车场景里会被旋转，画在正中 | ☐ |
| 3 | `pile` | 32×40 | 充电桩 | **浅色**，程序会叠灰、叠绿 | ☐ |
| 3 | `slot` | 32×60 | 车棚空车位 | **只画白色线框，中间透明**；程序会让它一闪一闪 | ☐ |

**关于 `bike`**：找车时，自己的车一开始也显示成 `bike_other`，和别人的车混在一起；玩家按 F 认出来之后，才换成 `bike` 并弹一下。所以 `bike` 要**和 `bike_other` 同款车型，但一眼能看出是"我的"**（比如整车黄色、或者醒目的黄色座套），这一换就是"找到了"的瞬间。

### 5. 音效清单

| key | 用在哪 | 要求 | 完成 |
|---|---|---|---|
| `beep` | 找车时的滴滴声 | **很短，0.1 秒左右**，离车越近播得越快（最快每 0.14 秒一次） | ☐ |
| `hit` | 骑行被撞 | 短促的撞击声 | ☐ |
| `fall` | 骑行摔倒 | 稍长一点、往下沉的声音 | ☐ |
| `park` | 找到车解锁、停好车 | 清脆的"叮" | ☐ |
| `plug` | 插上充电线 | "咔哒"一声 | ☐ |

- **做音效**：用 sfxr.me（网页版 jsfxr），点几下就能生成游戏音效，最快。
- **找素材**：用 freesound.org 的话，只选 CC0 协议的，避免版权问题。
- **格式**：必须是 mp3。导出的 wav 用 Audacity 或在线工具转一下。
- 没放音效时，`UI.sfx` 会自动用合成音顶替，不影响游戏。

### 6. 工具推荐

- **Piskel**（piskelapp.com）：网页版，免费，不用安装，新手首选。
- **Aseprite**：专业像素画软件，要付费；它的免费版叫 LibreSprite。
- **AI 生成**：可以用，但生成的图一般不是真正的像素格，背景也不透明。得先抠图，再用"最近邻"方式缩到指定尺寸，还要手动修一遍，其实不一定比自己画快。

## 第二部分：代码动效（A / B）

### 7. 还没有的动效：写法参考（Phaser 3）

已有的动效（闪烁、震屏、倒下、弹一下、路面滚动）不用重写，见第 8 节。下面是**还没实现**、要补的几种写法：

```js
// 1. 红闪：被撞、扫码失败（短暂变色后恢复）
target.setTint(0xff6666);
this.time.delayedCall(120, () => target.clearTint());

// 2. 粒子：摔倒扬灰、插线火花（Boot 里已经生成了白色小方块 'px'）
const dust = this.add.particles(0, 0, 'px', {
  speed: { min: 40, max: 120 }, lifespan: 400, scale: { start: 1, end: 0 },
  tint: 0xd6d3d1, emitting: false
});
dust.explode(12, this.player.x, this.player.y);

// 3. 左右晃一下：查看不是自己的车
this.tweens.add({ targets: bike, angle: 5, duration: 60, yoyo: true, repeat: 1 });

// 4. 吸到车位正中 + 弹一下：停好车（代替现在的瞬间 setPosition）
this.tweens.add({ targets: this.player, x: slot.x, y: slot.y, duration: 150,
  onComplete: () => this.tweens.add({ targets: this.player, scale: 1.2, duration: 100, yoyo: true }) });

// 5. 一亮一暗：坏掉的桩忽明忽暗、插上电后呼吸
this.tweens.add({ targets: pile, alpha: 0.4, duration: 500, yoyo: true, repeat: -1 });
```

**注意事项：**
- **转角度不会影响碰撞**：Arcade 物理的碰撞框不跟着转，所以倒车、晃车都可以放心用。
- **缩放会让碰撞框跟着变**：弹一下没关系，一直循环的晃动最好改角度，不要改大小。
- **叠色会覆盖原来的颜色**：找车、停车场景里 `bike_other` 本来就有随机叠色，用"红闪"后要恢复成原来的颜色，不能直接 `clearTint()`，要先记下原来的色值。
- **数字进 `config.js`**：按 `CLAUDE.md` 第 10 节，动效的时长、幅度如果要让 D 来调，就放进 `config.js`，不要写死在场景里。

## 第三部分：加分项与协作

### 10. 逐帧动画：放到加分项再做

真正值得画几帧的，大概只有主角走路（2～4 帧迈腿）。但这需要 3 处改动：

1. C 把几帧横着拼成一张图，比如 `player.png` 做成 128×32，里面是 4 帧 32×32
2. `assets.js` 每项加一个 `frames: 4` 字段
3. `Boot.js` 在 `frames` 大于 1 时改用 `load.spritesheet` 加载，并注册动画

第 2、3 条改的是 `CLAUDE.md` 里写死的约定，还是 A 负责的文件，按规矩要先在群里商量。**第一版不做**，用第二部分的代码动效就够演示了。

背景音乐也属于 `CLAUDE.md` 第 11 节的加分项，要等功能冻结前有空再做。

### 11. 协作注意

- C 只改 `assets/` 文件夹和 `src/assets.js`，别的代码文件不动。
- **每做好 3～4 张就提交一次**，不要攒到最后一起提交。
- 时间不够就只做第 1 批，剩下的保持色块也能正常演示。
- 动效不用等美术：A、B 现在就可以在色块上把待做的动效补上，C 的图放进来后会自动生效。
- 图放进来后，C 要进游戏看一下：叠色、旋转、夜晚滤镜下是否还看得清。
